# Security Policy / Sicherheitsrichtlinie

## Deutsch

### Unterstützte Versionen

Die installierte Produktversion steht im App-Footer (z. B. `Version: 4.3.031`).
Security-Updates gelten für die **aktuelle Minor-Linie und die drei vorherigen**.

| Version | Unterstützt        |
| ------- | ------------------ |
| 4.3.x   | :white_check_mark: |
| 4.2.x   | :white_check_mark: |
| 4.1.x   | :white_check_mark: |
| 4.0.x   | :white_check_mark: |
| < 4.0   | :x:                |

Ältere Stände, Forks und eigene Anpassungen sind nicht abgedeckt. Bei einem Minor-Bump (z. B. auf 4.4.x) verschiebt sich das Support-Fenster analog; diese Tabelle wird dann angepasst.

### Schwachstelle melden

Bitte melde Sicherheitslücken **nicht** als öffentliches Issue oder Pull Request, solange sie ungepatcht sind.

**Bevorzugt:** [GitHub Private Vulnerability Reporting](https://github.com/wum-hamburg/wum-ci4-accounting/security/advisories/new) für dieses Repository.

**Alternativ:** E-Mail an **info@wum.hamburg** mit Betreff `[SECURITY] …`.

Hilfreiche Angaben (kurz):

- Beschreibung der Schwachstelle
- Schritte zur Reproduktion
- betroffene Version (Footer) und Umgebung
- erwarteter vs. tatsächlicher Impact

### Ablauf und Erwartungen

- Wir bemühen uns um eine Bestätigung innerhalb von **ca. 7 Tagen**. Das ist eine Absichtserklärung, kein Anspruch.
- Nach Prüfung folgt ein Update (angenommen / abgelehnt / weitere Infos nötig).
- **Angenommen:** Nach Möglichkeit ein Fix auf unterstützten Linien bzw. `main`, ggf. ein Security Advisory. Keine Garantie für Frist, Umfang oder Backports.
- **Abgelehnt:** Kurze Begründung, soweit sinnvoll.
- Es gibt **keinen Anspruch** auf Patch, Timeline, Advisory oder Vergütung.

## English

### Supported versions

The installed product version is shown in the app footer (e.g. `Version: 4.3.031`).
Security updates apply to the **current minor line and the three previous ones**.

| Version | Supported          |
| ------- | ------------------ |
| 4.3.x   | :white_check_mark: |
| 4.2.x   | :white_check_mark: |
| 4.1.x   | :white_check_mark: |
| 4.0.x   | :white_check_mark: |
| < 4.0   | :x:                |

Older builds, forks, and custom modifications are out of scope. After a minor bump (e.g. to 4.4.x), the support window shifts accordingly and this table will be updated.

### Reporting a vulnerability

Please **do not** open a public issue or pull request for unpatched vulnerabilities.

**Preferred:** [GitHub Private Vulnerability Reporting](https://github.com/wum-hamburg/wum-ci4-accounting/security/advisories/new) for this repository.

**Alternatively:** email **info@wum.hamburg** with subject `[SECURITY] …`.

Useful details (brief):

- description of the issue
- steps to reproduce
- affected version (footer) and environment
- expected vs. actual impact

### Process and expectations

- We aim to acknowledge reports within about **7 days**. That is an intention, not a commitment.
- After review you will get an update (accepted / declined / more info needed).
- **Accepted:** A fix may be applied to supported lines / `main`, and a security advisory may be published. No guarantee of timeline, scope, or backports.
- **Declined:** A short reason when practical.
- There is **no entitlement** to a patch, timeline, advisory, or compensation.
